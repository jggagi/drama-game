## 1. 给美术合作方的项目说明

《雷雨：门外》是一款以四凤为主视角、围绕“离开这个家”展开的小体量探索式叙事游戏。玩家先替她准备与爱人离开的明天，在真相揭露后，重新处理住处、关系与自己的生活。

视觉重点不是复杂家谱，也不是猎奇秘密，而是：**同一间房、同一件衣服、同一个动作，在两个时刻具有不同意义。**

当前优先测试固定镜头的手绘舞台式 2D：小比例人物在室内移动，按需出现半身肖像，少量物件近景与关键插画。原有像素路线仍保留，需要在同构图样张上比较后决定。请不要把“手绘已经定案”“像素一定便宜”或“必须做全套立绘”作为报价前提。

第一次概念验证只服务两处空间、三位角色及两次收拾行李。完整版初稿的 3—4 小时目标、六到八处区域，以及全部八位角色，不等于本次委托范围。

### 接受工作的基本方式

先确认灰阶构图与动作，再决定风格、色彩与细节。每次提交注明资产编号、版本、完成度、对应分支和待确认问题。没有批准灰阶与风格测试之前，不要求合作方自行推进完整精绘。

创作批准由项目创作者负责；合作方可以提出更有效的镜头或造型，但涉及人物关系、出场位置、道具归属与结局含义的变化应先提出，不以美术完成度替代剧情确认。

## 2. 范围、优先级与交付性质

- **P0：首轮概念验证。** 当前建议启动的范围；产物用于判断方向，不默认能直接导入游戏。
- **P1：扩展概念包。** 在 P0 得到确认后，补充送药空间与三位周家角色，形成三场景、六角色的视觉提案。
- **P2：完整版增补。** 随逐场剧本确认另行拆单，不在本次默认报价内。

“基础场景＋光照草稿”意味着共享结构的状态研究，不是两张彼此无关的精绘背景。角色表情缩略、动作关键帧和完整动画循环也不是同一种交付物，报价应分开。

## 3. 共用画面与交付约定

### 3.1 画布与比例：先用于审图，不等于运行时规格

场景与关键画面以 `16:9` 构图，审图预览建议 `1920 × 1080`，另外提供 `1280 × 720` 的实际观看版本。没有批准风格之前，不必把草稿精修到大幅印刷分辨率。

手绘路线可按 1080p 视图起稿；像素路线可先用 `640 × 360` 逻辑画布，按整数倍展示到同样的评审视窗。像素方案保留原生画布，不把低分辨率图经过平滑放大冒充手绘。两条路线的 UI 都单独排版，不把中文字烧进低分辨率背景。

角色板与物件板可以使用便于阅读的竖版或横版，不强制同一画布。但必须附一个合成到实际游戏视图尺寸中的示例，避免只在放大的原画里成立。

### 3.2 P0 源文件与导出

提供可编辑分层源文件、通用 PNG 预览及简短说明。使用双方能读取的 PSD、KRA 或其他事先确认的格式，不强制某个品牌。提供 MP4 或 GIF 动作预览时，同时保留关键帧与可修改源文件；预览视频本身不是完整动画交付。

背景、人物、道具、文字和效果尽量独立。无需为概念稿过度切碎每块木板，但以后需要变化或交互的门、窗光、衣物和箱子不能全部不可逆地合并。

场景建议的逻辑层为：后景与墙体、家具与地面、可交互道具、人物参考层、门窗与前景遮挡、光影／天气、标注。人物参考层只用于验证构图，不直接烘焙进最终无人物背景。

文字保留可编辑内容；只记录字体名称和使用条件，不打包或提供字体文件。未确认使用范围的字形不能被当作正式发行资产。

### 3.3 命名与版本示例

使用稳定资产编号与 ASCII 文件名，中文说明放在索引中。例如：

```text
BG002_lu-room_base_draft_v001.png
BG002_lu-room_storm_draft_v001.png
CH001_sifeng_model-sheet_draft_v001.png
SQ001_packing-before-after_draft_v001.png
KF001_second-packing_mother-present_draft_v001.png
```

`draft`、`review`、`approved` 应与实际批准状态一致。合作方不得自行将文件改为 `approved`。同一身份的道具跨版本保持编号；不同分支需在文件名或交付索引中明确标注。

建议后续使用 `art/concepts/`、`art/characters/`、`art/props/`、`art/ui/` 与 `art/storyboards/` 分类；这些只是目录建议，**本次文档提交没有创建这些资产目录或文件**。大源文件的存储方式在确定体量后再决定，不在本轮引入新的资产管理系统。

## 4. AD001／AD002：艺术方向与路线比较 Brief

### 目标

判断本作在实际游戏尺寸下，能否同时保留空间关系、手部动作和人物的普通生活感。不是比赛哪种风格能画出最漂亮的宣传海报。

### 共用画面

鲁家房间内，四凤站在打开的箱子旁，正在折一件自己喜欢的新衣。侍萍坐在旁边的坐具上，手有伸出又停下的可能。门与一小块窗面可见，没有第三个人。

两条路线使用相同的房间布局、箱子方向、人物相对位置、衣物基底颜色与光源方向。第一轮用中性、易读的室内光，不靠大幅不同的滤镜替代风格差异。

### 需要提交

一张手绘静帧、一张像素静帧；每种各三格“拿起—折叠—放下”的关键帧；同一尺度的游戏视图预览；每条路线的预计制作环节、最难修改的部分和需要额外验证的事项。无需承诺未经实作验证的工期。

### 通过标准

衣物、手和箱口能区分；母亲不是背景装饰；动作无需读台词也能理解；第二次出现时能够识别同一物品。修改一次衣服长度或箱口位置后，合作方能说明需要连带修改哪些内容。

### 禁止偏差

不让两种路线分别使用完全不同的镜头或角色设计；不通过多画华丽家具让其中一条显得更高级；不采用幼态 Q 版来替代尚未解决的人物动作。

## 5. CS001：色彩脚本 Brief

一张五格时间轴，依次研究闷热、来客、第一声雷、暴雨和尾声。每格标注主光源、明暗焦点、背景冷暖关系与角色的可读性。具体选哪一幕中的哪个场景，可以在灰阶评审时确认；色彩研究不代表新增剧情场景。

第一格要让人相信这里仍然有日常生活与期待；第三、四格让熟悉环境变得不稳定，但人物与行动不能消失；最后一格保留平常生活的尺度，不做金色通关画面。

另取新衣的一块标准色，放在至少白天与雨夜两格中对照。灯光可以改变表观色，但观者仍需相信是同一件衣服。各幕不要简单统一套黄色、蓝色和黑白滤镜。

## 6. BG001：周宅后廊／门厅 Brief

**优先级：P0。情绪目标：你可以走过这里，但不一定有权在这里停下，把话说完。**

### 场景任务

容纳四凤与周萍的短暂独处、四凤与母亲改变谈话地点，以及第三人从可见入口出现的变化。画面必须支持“原地说”“移到旁边再说”“先离开”这些不同动作。

### 构图与布局

先画一张灰阶固定镜头布局。测试浅三分之四视角，前景有有限门框或柱边，中景留出双人交谈与错身的空间，后景具有可辨识的内室入口。侧向出口应能与内室入口区分，不要求复原尚未确定的完整宅邸平面。

提供三组人物站位叠加：两人私下谈话、第三人进入、有人站在门口但保留可商量的让路空间。人物位置图是制作参考，不直接呈现给玩家作为全知地图。

### 必须出现的视觉信息

门的开合方向、门槛或地面转换、光源、可站立区、至少一条清晰通路。物件可用整理得很整齐的柜、边桌或坐具表现秩序，不需要奢华陈列。

### 状态与分层

提交基础白天构图与傍晚光照草稿，共用几何结构。门的开／关可先在标注层示意，制作批准后才拆成实际状态资产。前景遮挡应与人物手部、可行走区分离。

### 避免

避免宏大庄园大厅、泛化老上海霓虹、诡异人影、迷宫式走廊；不要把一关门就变安全当成视觉事实。不要把所有出口埋进近黑色背景。

### 验收提问

遮住台词后，能否指出谁在对谁说话、谁能离开、第三人从哪里出现？放上三条选项与姓名栏之后，门与关键人物是否仍看得见？同一个空间能否容纳温柔和压力，而不是只有阴森？

## 7. BG002：鲁家房间 Brief

**优先级：P0。情绪目标：这是一间有人认真过日子的有限空间；一个计划崩塌，不等于整间屋子和全部生活都失去价值。**

### 场景任务

支撑两次收拾行李、母女交谈、真相后的停顿与重新决定去向。核心操作区域围绕箱子、衣服和人，而不是围绕一面证据墙。

### 构图与布局

中景布置箱子与可整理衣服的表面；旁边留一把可供母亲坐下的坐具；床、桌、门和有限窗面形成生活结构。人物可以靠近、退开或自己完成折衣动作，不应被道具塞满的房间挤得只能面对镜头站立。

交互焦点最好位于画面中央偏一侧，为对白与选择留下安全区，但不要把全场布置成围绕 UI 的空摄影棚。提交无遮挡布局图和前景遮挡图，确认重要手势不会被床沿或桌角挡住。

### 核心物件

旧箱子、新衣、针线包、折叠纸页、坐具、床或可放衣物的平面。箱子材质与闭合方式先测试一种清楚且时代可信的普通设计，待资料核查后定案；不擅自加入现代拉杆箱、塑料扣件或带轮旅行箱。

### 两个状态

白天／第一次：有期待，但仍是普通房间。雨夜／第二次：窗面和光线改变，主体几何不变。保持箱子的五金位置、布料花纹与已有磨损，变化只来自叙事允许的物品状态和人物动作。

基础场景留出母亲在场与不在场的可能，不把她画死在背景中。关门、椅子位置和衣物归属的改变，应有对应剧情动作，不为了构图擅自发生。

### 避免

避免把贫穷画成垃圾堆、坍塌危房或持续漏水；避免温馨滤镜强迫母女关系已经和解；不要新增家庭照片、幼儿用品或纪念物来暗示尚未确认的身世与后续人生。

### 验收提问

两张状态图叠加后，能否确认它们是同一个房间？去掉眼泪与对白，是否还能通过手势看出两次收拾不同？四凤能否自己合上箱子、走向出口，而不是必须由其他角色代做？

## 8. BG003：周宅内室／送药空间 Brief

**优先级：P1，非首轮前置。情绪目标：房间不必可怕，但它有一套要求别人服从的秩序。**

这是送药与三人权力关系的测试空间，暂不确定为繁漪私人卧室。以日后逐场剧本对地点的确认优先。

画面容纳繁漪的坐处、周朴园无需频繁移动便能影响谈话的位置、四凤端托盘进入的路线，以及一处可放下药碗的位置。构图不要求机械居中：可以通过别人绕过家具与主人不必让路的对比表达权力。

提交三组站位：药被端到面前、繁漪不接、四凤等待或放下。必须让药碗、四凤的手与接收者反应可见；不要用巨大桌子把全部动作挡住。

材质精细、维护得当，光线有节制。避免宫廷化、教堂式权威构图、色情化卧室或魔鬼式阴影。验收时应能回答：**谁在要求谁？真正承担这个要求的身体是谁的？**

## 9. CH001—CH008：角色 Brief

### 9.1 共用要求

每张首轮角色板包含全身站姿、半身基准与三个表情缩略，表情数量含中性。附比例、衣物层次、头发轮廓与主要色块说明。先做可以保持一致的角色，再扩展表情和服装，不以大量差分掩盖身份不稳定。

人物确切年龄、发型制式、服装名称与年代细节待原作与资料核查，不通过“看起来像某位演员”来偷懒定型。各人可以漂亮、普通、疲惫或精神，但面貌不能直接等同于道德标签。

### CH001 四凤｜P0

她首先是动作利落、会做事、也在意自己喜欢什么的人。衣服有洗涤和修补的痕迹，但不破败；袖口和整理衣摆的习惯可以体现她的个人选择。不要把年轻等同于儿童化。

首轮表情：中性专注、真实的期待、受到冲击后仍在听。额外动作由 SQ001 表现，不在角色板里用夸张握拳或仰头证明成长。

全身基准要能端物、弯身取衣、坐下和在门口停住。新衣不是默认已经穿在身上，也不是默认恋人赠送。情感目标是让人相信她确实可能喜欢这件衣服，而不是让角色像在展示商业皮肤。

验收重点：角色放回游戏尺寸后仍然利落可辨；劳动感不依赖脏污；换一个情绪仍是同一个人；手部没有被宽大袖口永久遮蔽。

### CH002 侍萍｜P0

衣物耐穿、整洁、反复使用。手与肩部体现长期劳动，但不刻意把她画得年迈到失去个人生活。她的稳定感与保护中的强硬，应同时存在。

首轮表情：克制的中性、准备追问、想接近女儿却停住。表情不是三种哭法。姿态要能与四凤共同演出“伸手—被回应—收回或停住”，同时保留独立站立和坐下时的尊严。

验收重点：不依赖皱纹数量制造悲惨；与四凤同框时不是附属的苦难标志；不通过微笑提前宣布母女和解。

### CH003 周萍｜P0

体面、受教育、衣料相对精细，但不是奢华偶像。设计需要支持私下的温柔与被要求明确承担时的退缩，两者不是两张互不相干的脸。

首轮表情：中性、真正在听四凤说话、面对追问的迟疑。动作注意视线落点、肩与身体轻微后撤，不用邪笑、黑眼线或大面积面部阴影说明人物问题。

验收重点：玩家能理解四凤为什么爱过他；同时不能靠画面自动赦免他的行为。衣着在周宅和鲁家画面中仍有一致性。

### CH004 繁漪｜P1

质量较好的衣料与清晰轮廓，深绿、酒红等仅作为试色。先建立静止时的克制与疲惫，再研究突然靠近时的压力。首轮表情为中性、警觉、受伤后的锋利。

她不是“危险女人”装饰，不以裸露、疯乱发型或永恒冷笑体现冲突。服饰允许漂亮，但漂亮不能代替人物复杂性。

### CH005 周朴园｜P1

衣着稳定、维护良好、深色轮廓。通过坐姿、等待别人回应、很少需要主动让路表现空间权力。首轮表情为中性、等待服从、受到质疑后的控制。

不要求夸张威严或不断愤怒。他不必占画面最大面积，仍可以成为让其他人调整站位的人。

### CH006 周冲｜P1

保留学生气、相对轻快的轮廓与向外看的姿态。首轮表情为中性、热心、理想受到现实阻碍时的困惑。与周萍在年龄感、肩颈松紧和动作节奏上区分，不靠把他画成儿童。

真诚不意味着成熟可靠；失落不以滑稽表情处理。角色不是恋爱路线的奖励或失败选项。

### CH007 鲁大海｜P2

体现劳动与户外生活，不做肌肉英雄或只会愤怒的莽汉。动作明确，身体较向前；与家人相处时也能停顿和观察。后续表情与服装细节根据其独立剧情确认，不只为接走四凤设计。

### CH008 鲁贵｜P2

在有限条件下努力维持体面，习惯观察别人的回应。对上与对下的姿态差异比夸张油滑的脸更重要。不用肥瘦、秃发或滑稽五官直接编码贪婪；保留他作为家庭成员的日常状态。

## 10. PR001／PR002：道具连续性 Brief

| 物品编号 | 物品 | 首轮必须说明的状态 | 连续性要求 |
| --- | --- | --- | --- |
| PR101 | 行李箱 | 关闭、打开、内部基本结构 | 箱口方向、铰接／闭合方式、磨损位置不随镜头变化 |
| PR102 | 新衣 | 展开、拿在手中、折好 | 同一款式、同一基础色、同一尺寸；不自动变成婚服 |
| PR103 | 针线包 | 收起、打开 | 体积可放入箱中；出现与否继承玩家选择 |
| PR104 | 明日清单 | 折起、展开、局部补写／划去 | 旧条目仍可辨；UI 转写层不强行成为人物流畅亲笔 |
| PR105 | 信 | 未交出、拿在手中、已经交给他人 | 信封与纸张身份一致；不得自动加入透露秘密的真实正文 |
| PR106 | 钱袋／工钱载体 | 收起、打开查看 | 具体币种、金额与年代样式待核对；不为美术补设财富变化 |
| PR107 | 托盘，P1 | 端持、放下 | 双手接触和药碗相对位置可行 |
| PR108 | 药碗，P1 | 托盘中、手中、桌上 | 碗的尺度、握持与液面不随画面任意变化 |

首轮只做概念状态草图，不默认每个状态都需要一套成品动画。正式生产时依据镜头实际可见程度拆分。

需要一个简单的连续性说明页：每件物品的编号、基础色、尺度参照、正反面差异，以及哪些分支可能不持有它。不要额外发明神秘吊坠、血缘信物、婴儿纪念物或侦探证据板。

## 11. UI001／UI002：界面 Brief

### UI001 对话与选择

在 BG001 的实际构图上叠加界面，不单独在空白画布上做漂亮按钮。首轮需要默认状态、长文字状态、字号放大 150% 状态。明确姓名、正文、三条选择和输入焦点。

样本文字只用作排版测试，不视为新增定稿台词：

> 四凤：我想先和娘把明天住在哪里说清楚。周萍答应的安排，我也要当面问过。

选择示例为“请娘到后廊再说”“现在请周萍过来”“我先不回答”。不配善恶颜色、星级、好感数或剧情成功率。选项过长时重排，不截断含义。

中文正文优先屏幕可读性，1080p 默认先用约 26—30 px 测试，再在 720p 下查看。旧纸纹理放在文字下方的低干扰区域，不让褶皱穿过关键字。字号放大后允许面板适度扩展、分页或滚动，不能盖住正在发生的关键动作。

肖像可以占一侧，但需要保留说话者、另一位在场者及门的位置。第三人进入时，可以切换为更紧凑的肖像或不显示肖像，不把空间叙事埋在立绘后面。

### UI002 明日清单

同一张纸做三个状态：最初仍有模糊承诺、部分安排已经落实、真相后需要重新安排。纸面短词可以是“工钱”“住处”“新衣”；较长解释采用独立的可读转写层。

对三类内容采用文字和简单记号共同区分：别人承诺、已经落实、尚未决定。真相后可以划去仍未成立的“与周萍共同离开”安排，但不能清空工钱、所有物品或四凤个人愿望。

不要出现“大失败”“任务全部重置”“获得自我觉醒”等系统判词。记录应该像生活安排，不像抽象成长结算。

### 共用验收

界面在实际分辨率可读；对话不会挡住门和手；焦点清楚且不依赖颜色；所有关键互动都有非精准拖拽的操作表达；画面不提前泄露隐藏在场者、血缘关系或结局条件。

## 12. SQ001／KF001：两次收拾行李 Brief

### SQ001：十二格成对分镜

两排各六格，上排第一次，下排第二次。尽可能沿用同一机位、箱子朝向与物件布局，让比较集中在动作和意义上。

| 格 | 第一次 | 第二次 |
| --- | --- | --- |
| 1 | 看见已打开的箱子，四凤进入整理位置 | 回到同一箱子，保留短暂停顿 |
| 2 | 拿起新衣，注意到自己喜欢的颜色或细节 | 拿起同一件新衣，尚未决定如何处理 |
| 3 | 母亲准备帮忙；关系中仍有催促与不耐烦 | 母亲想帮忙，但等待四凤的回应 |
| 4 | 四凤按原来计划折衣 | 四凤选择自己折，或采取其他剧情允许的处理 |
| 5 | 衣服放进箱子，成为共同计划的一部分 | 对应保留分支，衣服因自己的选择放回箱内 |
| 6 | 合上或暂时放开箱盖，期待下一步 | 自己完成整理；计划改变，但行动仍能继续 |

每格注明玩家可操作、对白停顿或镜头过渡，不能全部标成自动播放。演出测试需要看得出哪里应把控制权交还玩家。

母亲在场的这条分镜是一个具体分支，不代表所有路线。其他路线可复用房间与物件近景，不默认制作同样数量的插画。

### KF001：第二次收拾关键画面

**一句话画面：母亲的手停住了，女儿正在把自己挑的衣服折好。**

使用鲁家房间已有布局。四凤的手、衣物与箱口是主要焦点；侍萍的手、坐姿和距离形成第二焦点。门或窗只是空间锚点，不争抢注意力。

表情克制，不以大颗眼泪代替动作。可以让母亲坐着、四凤站着或俯身，但姿势必须便于真实折衣，不是为海报摆出的形体。衣服必须能与 PR102 的设计对上。

提交灰阶构图及光照草稿即可进入评审。绘制精细成品前，先确认画面是否保留实际动作、是否只适用于母亲在场分支、是否会替玩家执行关键选择。

不要加入拥抱、跪地、恋人幽灵、白色婚纱、破碎镜子、象征新生的巨大日出或未经剧本确认的新物件。人物此刻可以没有和解，也可以不知道下一站去哪里。

**验收问题：去掉字幕以后，画面能否仍然表达“她开始自己处理这件事”，而不只是“她很悲伤”？**

## 13. AN001：动作测试与后续生产边界

首轮只验证两个动作组，不制作完整角色运动库。

**折衣组：**拿起、展开到足够辨认、折叠、放入箱中。先做四到六个关键姿态，再用粗线或灰模组成简短预览。复用 AD002 已批准路线的折衣草稿，不重复委托同一项探索。

**门口组：**走近、因在场人物停下、对方让出位置、通过门口。需要两个人与门框的比例测试，避免“门已经空着，角色却撞 invisible wall”的表现。这里描述可见动作，不预设所有 NPC 都会让路。

正式生产前才决定移动方向数、帧数、骨骼结构、角色 pivot、碰撞区域和导出图集。端药、递信与坐起可先保留文字动作说明，待相应场景进入制作再扩展。

动画不能用拉长四肢或穿透道具凑出动作；衣服与手的接触连续；镜头切换不重置道具去向。关键画面里的复杂手部可以使用局部重绘，不要求与探索移动采用同一种技术。

## 14. 从概念到可用资产：必须分开的验收

| 概念验收 | 进入原型生产后另验收 |
| --- | --- |
| 情绪与人物方向成立 | 游戏内尺寸、运行效果和实际可读性 |
| 构图能容纳角色与 UI | 碰撞、遮挡顺序、门与物件状态切换 |
| 同一身份与物品保持一致 | 跨镜头、跨动画、跨存档状态的一致性 |
| 动作关键帧可理解 | 动画接触点、循环、过渡与输入响应 |
| 来源和可用范围已标注 | 项目批准使用的最终资产清单 |

生产交接还应提供统一画布与锚点、需要交互的物件独立层、可走区与遮挡参考、门与箱子状态说明、透明边缘检查、可编辑 UI 与对应文本。具体格式在路线和引擎确定后填写，不因为概念稿是 PNG 就当作技术对接已经完成。

本次文档不指定引擎、实时生成服务或自动化美术流水线。静帧好看与游戏能玩是两个不同的通过条件。

## 15. 评审、报价与返修方式

### 15.1 建议评审顺序

先评 AD001 与 BG002 灰阶；再评 AD002 两条路线；路线选定后评三位角色及两处空间；随后评色彩、UI 与道具连续性；最后评两次收拾分镜、关键画面和动作测试。

每轮只回答与当前完成度相符的问题。灰阶阶段不纠缠衣料细花纹；人物身份未定，不扩展十几种情绪；分镜未成立，不以精修插画掩盖。

### 15.2 分项报价应包含

| 字段 | 需要说明 |
| --- | --- |
| 项目编号与阶段 | 例如 BG002／P0，不能只写“背景若干” |
| 数量与精度 | 基础构图、状态草稿、精绘成品分别计量 |
| 交付内容 | 源文件、PNG、标注、动作预览分别列明 |
| 修改范围 | 建议按草图与上色分阶段约定轮次；具体次数与费用协商，不视为已约定 |
| 依赖与排期 | 在什么内容获批后开工，由合作方依据范围提出；本稿不预设工期 |
| 可用范围与来源 | 自制、第三方材料、生成素材分别说明；有疑问的资产先标待核实 |
| 扩项条件 | 新角色、新镜头、新分支、服装重设、已批准布局重做需单列变更 |

先评估“让核心场景成立的最小投入”，不是一次性给整个完整版打包报价。报价与付款、署名、交付和使用范围由双方另行确认，本文不是已经达成的商业合同。

### 15.3 统一反馈格式

```text
资产编号／版本：
对应场景或分支：
已经成立的部分：
需要修改的问题：
问题属于：剧情连续性／构图可读性／造型一致性／动作／风格／技术
必须保留的要素：
下一次只需验证的事情：
状态：继续草图／进入上色／待创作决定／批准概念
```

反馈尽量指向可观察的问题，例如“对白框挡住了母亲伸出的手”，而不是只说“再高级一点”“更有民国感”。“批准概念”不等于批准直接进入商业发行。

## 16. 参考资料与使用记录

服装、家具、箱子和纸张等先记录资料，再决定具体细节。艺术情绪参考和原作／年代依据分开，不用一部风格化电影的画面替代历史考据。

建议参考登记字段如下；这里只提供格式，没有宣称资料已经完成收集或取得许可：

| 字段 | 内容 |
| --- | --- |
| 参考编号 | 稳定编号 |
| 来源 | 作者、机构、版本、网页或馆藏标识 |
| 参考类型 | 原作依据／年代物件／构图情绪／自制研究 |
| 对应资产 | 例如 BG002、PR101 |
| 使用方式 | 仅用于理解、临摹研究、拟纳入交付等，区分清楚 |
| 使用范围状态 | 已核实／待核实／不得直接纳入 |
| 改动与风险 | 是否混用年代、是否存在可识别的他人角色或构图 |

不直接复制电影画面、演员肖像、他人游戏角色或未经确认范围的素材。采用生成式工具时，记录工具、输入来源与人工修改；输出仍需人物身份、手部、文字、时代物件和来源检查，不默认具有统一风格或已经完成权利核查。未公开的项目资料在外发工具前需由项目创作者确认。

## 17. 首轮完成标准

首轮应留下可比较的风格样张、两处可解释其行动路径的空间、三位稳定的角色、连续的关键物件、实际尺寸可读的 UI，以及两次收拾的成对动作方案。

需要在评审记录中明确：哪些已经认可，哪些还只是候选；哪些是草稿，哪些经过实际尺寸或动作测试；哪些资料仍待核实。没有实际测试，不写“已通过可读性测试”；没有实物，不用占位文件冒充已交付资产。

真正的通过条件不是“美术包看起来很丰富”，而是：**玩家能先相信四凤正在准备一个明天，再看见她用同一双手，为改变后的生活重新收拾行李。**
